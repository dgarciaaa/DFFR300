Criterios Generales de Correccion

  • Se evalua la comprension del problema, la traduccion correcta a un algoritmo y la coherencia logica de la solucion.
  • Se aceptan distintas implementaciones correctas si resuelven lo pedido de manera funcional.
  • El estudiante puede asignar el nombre que desee a las variables mientras se usen correctamente y sean coherentes con el problema. Si define con errores una variable, sus siguientes llamados no deben considerarse como errores de arrastre si son coherentes con la logica del problema.
  • No se evalua principalmente el estilo de programacion, sino el entendimiento del problema y la solidez de la logica.
  • Cuando exista una idea correcta pero una implementacion incompleta, corresponde asignar puntaje parcial y explicar con precision que parte esta lograda y que parte falla.
  • Un error menor de sintaxis, formato de salida o detalle secundario no debe anular por completo una solucion cuyo enfoque general sea correcto.
  • La correccion debe ser pedagogica y razonable. No se debe castigar como error grave una decision tipica de principiante si no rompe la logica principal del ejercicio.
  • Si el estudiante agrega pasos innecesarios, variables auxiliares redundantes o una organizacion poco elegante, eso no debe considerarse automaticamente incorrecto si la solucion igualmente resuelve lo pedido.
  • Cuando el enunciado pide trabajar con arreglos o columnas completas, la solucion debe operar sobre toda la coleccion o recorrerla de forma coherente. Se aceptan soluciones vectorizadas con NumPy/pandas o ciclos for si entregan los mismos resultados conceptuales.
  • Si la idea central esta bien encaminada, corresponde privilegiar puntaje parcial alto antes que una penalizacion excesiva.
  • Se debe distinguir entre un error conceptual importante y un detalle menor de implementacion. Solo los errores conceptuales que rompen el objetivo del problema justifican una baja fuerte de puntaje.
  • Si una solucion funciona en lo esencial, aunque sea torpe, redundante o propia de un nivel inicial, debe valorarse como una respuesta valida o parcialmente valida, no como una respuesta nula.

PROBLEMA 1: Ajuste cuadratico y estimacion de un umbral

Evalua un programa que ajusta un modelo cuadratico a datos experimentales de radiacion: d = [0, 1, 2, 3, 4, 5, 6] y R = [1.2, 2.0, 4.1, 6.9, 10.8, 16.2, 22.1].

El programa debe usar un ajuste cuadratico, calcular valores ajustados, residuos y R2, estimar el valor de d para el cual R = 12, graficar datos y curva ajustada, e interpretar por que no cualquier raiz del polinomio es una solucion fisicamente aceptable.

Orientacion de correccion

  • Debe privilegiarse que el estudiante comprenda la secuencia general: cargar los datos, ajustar un polinomio de grado 2, evaluar el modelo, medir la calidad del ajuste y resolver el umbral pedido.
  • El ajuste puede implementarse con np.polyfit(d, R, 2), np.polyval o una forma algebraicamente equivalente.
  • Para el umbral, lo importante es resolver el modelo ajustado igualado a 12 y quedarse con una raiz real y fisicamente razonable, normalmente dentro del rango de medicion o al menos positiva y coherente con el problema.
  • Un grafico con etiquetas simples no debe castigarse con dureza si muestra datos, curva ajustada y referencia del umbral de manera interpretable.
  • Solo debe bajarse fuertemente el puntaje cuando no aparece el ajuste cuadratico, cuando el umbral se calcula sin relacion con el modelo, o cuando los residuos/R2 quedan desconectados de los datos ajustados.

PROBLEMA 2: Ordenamiento y busqueda de periodos orbitales

Evalua un programa que trabaja con periodos = [12.4, 3.1, 8.7, 25.0, 1.9, 14.2, 6.5, 18.3]. El programa debe implementar bubble sort, contar comparaciones e intercambios, mostrar lista original y ordenada, calcular minimo y maximo, implementar busqueda binaria y buscar 14.2 y 10.0.

Orientacion de correccion

  • Debe privilegiarse que el estudiante comprenda que la busqueda binaria requiere una lista ordenada y que el ordenamiento debe producir una secuencia ascendente.
  • Si el enunciado pide bubble sort, usar sort() o sorted() puede recibir puntaje parcial en el item de ordenamiento si el resto del flujo es correcto, pero no debe recibir puntaje completo en la implementacion del algoritmo pedido.
  • El conteo de comparaciones e intercambios puede variar levemente segun detalles de implementacion, siempre que sea coherente con el bubble sort.
  • El indice devuelto para 14.2 debe corresponder a la lista ordenada. Tambien es aceptable entregar una posicion clara en lenguaje natural, siempre que no confunda lista original con lista ordenada.
  • Solo debe bajarse fuertemente el puntaje cuando no se ordena la lista, cuando la busqueda binaria se aplica sobre datos desordenados, o cuando las busquedas pedidas no se realizan.

PROBLEMA 3: Limpieza y resumen de un catalogo estelar con pandas

Evalua un programa que lee catalogo_estrellas_s3.csv, inspecciona el DataFrame, limpia filas con datos faltantes en columnas numericas relevantes, calcula luminosidad_rel = radio_Rsol**2 * (temperatura_K/5778)**4, resume por tipo estelar y grafica temperatura versus luminosidad relativa.

Orientacion de correccion

  • Debe privilegiarse que el estudiante comprenda el flujo de trabajo con pandas: lectura, inspeccion, limpieza, nueva columna, agrupacion y visualizacion.
  • La limpieza debe enfocarse en columnas necesarias para los calculos numericos, como temperatura_K, radio_Rsol, distancia_pc y magnitud_V. No se debe castigar con dureza si el estudiante decide eliminar tambien filas con otros datos faltantes, siempre que explique o mantenga coherencia.
  • La formula de luminosidad relativa debe usar radio al cuadrado y temperatura normalizada a 5778 elevada a la cuarta potencia.
  • La agrupacion por tipo puede usar groupby, agg, describe, conteos y medias/desviaciones, siempre que entregue un resumen interpretable por categoria.
  • Solo debe bajarse fuertemente el puntaje cuando no se usa pandas para leer/procesar el catalogo, cuando la luminosidad relativa no usa las columnas correctas, o cuando el resumen por tipo queda ausente.

Observaciones complementarias

  • Si el estudiante usa una solucion vectorizada o una solucion con ciclos, ambas deben considerarse validas si calculan y presentan los resultados pedidos.
  • Si una solucion contiene errores de nombres de variables, pero la logica principal y los calculos son claros, corresponde asignar puntaje parcial segun los items afectados.
  • Los errores de grafico, etiquetas, plt.show() o formato de impresion no deben anular los calculos correctos. Deben afectar principalmente el item de visualizacion o salida.
  • En los tres problemas, un error de arrastre no debe castigarse varias veces si el estudiante mantiene una logica coherente a partir de una definicion inicial equivocada.
  • En el problema de ordenamiento, usar funciones nativas de ordenamiento puede demostrar que el estudiante entiende el resultado esperado, pero no reemplaza completamente la implementacion de bubble sort si ese algoritmo fue pedido explicitamente.
